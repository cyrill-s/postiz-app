# Vercel AI SDK: applicability to Kie and shared generation orchestration

Verified 2026-09-21 against npm `latest` tarballs, not just documentation. No paid provider requests were made. Versions: `ai` **7.0.107**, `@ai-sdk/provider` **4.0.17**, `@openrouter/ai-sdk-provider` **3.1.0**. OpenRouter declares peer dependency `ai: ^7.0.0`. These are observations of published releases, not a recommendation to upgrade existing applications indiscriminately. [ai manifest](https://unpkg.com/ai@7.0.107/package.json), [provider manifest](https://unpkg.com/@ai-sdk/provider@4.0.17/package.json), [OpenRouter manifest](https://unpkg.com/@openrouter/ai-sdk-provider@3.1.0/package.json).

## What can be reused

**Text:** `LanguageModelV4` standardizes both `doGenerate` and `doStream`; the model supplies provider/model identity and supported media URL patterns. This is a useful boundary for a Kie adapter, enabling shared AI SDK text tooling. It is not sufficient to return only a string: the adapter must map structured content, usage, finish reasons, tool calls, warnings and stream events correctly. [Interface](https://unpkg.com/@ai-sdk/provider@4.0.17/src/language-model/v4/language-model-v4.ts), [generate result](https://unpkg.com/@ai-sdk/provider@4.0.17/src/language-model/v4/language-model-v4-generate-result.ts).

**Images:** `ImageModelV4` has only `doGenerate`, not start/status operations. Its result requires base64 strings or binary images; a Kie implementation returning only remote result URLs would need to download the images or expose a separate URL-oriented API. A convenience Kie adapter can submit, poll and download inside `doGenerate`, but this conceals the accepted job from the caller until completion. It is therefore insufficient as the only interface for restartable image workflows. [Interface](https://unpkg.com/@ai-sdk/provider@4.0.17/src/image-model/v4/image-model-v4.ts), [result](https://unpkg.com/@ai-sdk/provider@4.0.17/src/image-model/v4/image-model-v4-result.ts).

**Video:** Contrary to older descriptions, current AI SDK supports a durable asynchronous interface. `experimental_startVideo` returns a JSON-serializable opaque `operation`; `experimental_getVideoStatus(model, { operation })` performs a single status check and returns pending/completed/error. The application can persist the operation and resume in another process. Both APIs require adapter implementation of `doStart`/`doStatus`; support in core does not imply support in every provider. The application must also persist enough provider/model information to reconstruct the correct model. [Start source](https://unpkg.com/ai@7.0.107/src/generate-video/start-video.ts), [status source](https://unpkg.com/ai@7.0.107/src/generate-video/get-video-status.ts), [V4 video interface](https://unpkg.com/@ai-sdk/provider@4.0.17/src/video-model/v4/video-model-v4.ts).

Video also supports provider webhook integration, automatic polling and `doGenerate` convenience calls. These exports remain explicitly experimental. They supply useful protocol plumbing but do not store application jobs, enforce business budgets or define cross-provider fallback policy. [Generation implementation](https://unpkg.com/ai@7.0.107/src/generate-video/generate-video.ts).

## OpenRouter adapter: a material integration gap

Published OpenRouter 3.1.0 exposes language, image and video models. However, `OpenRouterVideoModel` implements only `doGenerate`. It submits `POST /videos`, then privately polls `GET /videos/{jobId}` with defaults of 2 seconds between polls and 10 minutes total. It does **not** implement `doStart` or `doStatus`, so `experimental_startVideo(openrouter.videoModel(...))` cannot supply a durable operation and throws for lack of `doStart`. [Published declarations](https://unpkg.com/@openrouter/ai-sdk-provider@3.1.0/dist/index.d.ts), [published implementation](https://unpkg.com/@openrouter/ai-sdk-provider@3.1.0/dist/index.js).

There is also a concrete retry hazard. That adapter marks its polling timeout as `APICallError` with `isRetryable: true`. AI SDK's `generateVideo` retries the **entire** `doGenerate` call, with two retries by default. Thus a timeout after acceptance can cause another submission: up to three POST requests for one logical call. This is a source-derived risk, not a demonstrated billing incident; provider-side deduplication was not verified. Use `maxRetries: 0` for this combined submission/polling adapter until the application has safe reconciliation or a split start/status implementation. [Adapter implementation](https://unpkg.com/@openrouter/ai-sdk-provider@3.1.0/dist/index.js), [generateVideo retry boundary](https://unpkg.com/ai@7.0.107/src/generate-video/generate-video.ts), [retry defaults](https://unpkg.com/ai@7.0.107/src/util/prepare-retries.ts).

The newer `startVideo` generates one idempotency header outside its retry closure, preserving a caller-provided header. That improves transport behavior but cannot guarantee Kie or any custom adapter honors idempotency. Nor does an automatically generated key survive a completely new application call unless the application persists and supplies its own key. [Start implementation](https://unpkg.com/ai@7.0.107/src/generate-video/start-video.ts).

## Fallback: three different mechanisms

1. **`customProvider.fallbackProvider`: model lookup.** Used when the requested model identifier is absent from a custom registry. It does not retry a failed generation on another provider. [Official reference](https://ai-sdk.dev/docs/reference/ai-sdk-core/custom-provider), [implementation](https://unpkg.com/ai@7.0.107/src/registry/custom-provider.ts).
2. **`maxRetries`: retry the same operation.** Core retries errors classified retryable. This is not a Kie → OpenRouter routing policy, and wrapping submit-plus-poll makes its retry boundary significant. [Retry implementation](https://unpkg.com/ai@7.0.107/src/util/retry-with-exponential-backoff.ts).
3. **AI Gateway `order`/`models`: hosted routing.** Vercel documents provider ordering and fallback models for its separate Gateway service. This does not establish a ready-made route for independently accepted Kie media tasks or prove recovery of those task identifiers. [Gateway provider options](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options), [model fallback announcement](https://vercel.com/changelog/model-fallbacks-now-available-in-vercel-ai-gateway).

## Architecture recommendation (inference)

Keep a reusable Kie transport SDK. Use AI SDK for interoperable text behavior and optional image/video convenience adapters. Share a small generation orchestrator between Postiz and aibot, with application-supplied policy; do not attempt to reproduce AI SDK's entire LLM ecosystem.

The orchestrator should persist operation and attempt identifiers, chosen provider/model, idempotency key, and input/capability requirements. It should distinguish rejected submission, accepted/pending operation, terminal failure, and unknown outcome. Timeout or broken polling after acceptance should first resume/reconcile the same task. Starting another paid provider operation must be an explicit policy transition, not a generic retry.

For restartable media, define one application-facing submit/status contract across images and video. A Kie implementation can use the existing task APIs; OpenRouter video needs a split adapter or direct API implementation because its published adapter currently hides submission. AI SDK's experimental video operation can be wrapped behind that contract, limiting experimental interface changes to the integration layer. Database, Temporal, user billing and scenario-specific workflows remain outside the shared provider package.

For streams, decide fallback before emitting user-visible output, or expose a clear failed attempt/restart boundary; simply concatenating a second provider's stream after a partial first answer is not equivalent to retrying a request.

Acceptance test: successful Kie image; rejected Kie submission followed by compatible OpenRouter fallback; accepted Kie task followed by process restart and status recovery without new submission; transient status failure without fallback; terminal failure followed by policy-authorized fallback; partial text stream failure without silent success. These tests determine fit more reliably than provider counts.
