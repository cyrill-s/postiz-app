# Подключение канала MAX

В Postiz добавлен провайдер `max`: публикация сразу и по расписанию через собственного бота. Отдельное подключение для каждого канала; один бот может обслуживать несколько каналов.

## Подключение

1. Создайте бота на платформе [MAX для бизнеса](https://business.max.ru). Скопируйте его токен: Чат-боты → ваш бот → Расширенные настройки → Настроить.
2. Добавьте бота в канал администратором и разрешите публикацию (`write`). Для комментариев также разрешите чтение (`read_all_messages`) и включите комментарии в настройках канала. Чтение постов необходимо и для статистики.
3. Получите числовой `chat_id` канала из события `bot_added` вашего бота. Для бота с настроенным webhook событие приходит на его обработчик. Для нового бота без webhook можно получить событие через `GET /updates` при первоначальной настройке. Если событие уже потеряно, удалите и заново добавьте бота в канал после настройки получения событий. Не отключайте действующий webhook ради подключения Postiz.
4. В Postiz выберите «Добавить канал» → MAX. Введите токен бота и `chat_id`, включая минус, если он есть. Ссылка `max.ru/...` вместо ID не подходит.
5. После подключения создайте публикацию и выберите MAX. Для проверки подключения отправьте тестовый пост в свой тестовый канал.

[Официальная инструкция получения chat_id](https://dev.max.ru/docs-api#Получение-chat_id). С июня 2026 года `GET /chats` отключён: автоматический список каналов через этот метод не используется. Postiz не подписывает бота на события и не меняет его webhook.

## Поддержка

- Обычный текст и ссылки, до 4000 символов.
- До 10 вложений: изображения до 50 МБ каждое, видео до 250 МБ каждое. Ограничения форматов и размеров изображения (до 7680 × 7680) дополнительно проверяет MAX.
- Публикация только с медиа, без текста.
- Повтор отправки при явных ответах `attachment.not.ready` и HTTP 429, без повторной загрузки файлов.
- Комментарии к своим постам через обычную кнопку «Добавить комментарий» в редакторе Postiz, с индивидуальными задержками. Каждый комментарий публикуется под исходным постом, а его ID сохраняется как ID отдельного элемента цепочки.
- Комментарии: до 4000 символов, с форматированием, без фото и видео. Встроенные гиперссылки преобразуются в текст вида `название (https://...)`; предпросмотр и проверка длины учитывают этот же результат. Вложения в комментарии блокируются в редакторе и на сервере.
- Ссылка на публикацию берётся из ответа MAX. Если MAX её не возвращает, Postiz сохраняет ID поста без выдуманной ссылки.

При сетевом сбое или HTTP 5xx во время отправки провайдер не повторяет запрос автоматически: MAX не предоставляет ключ идемпотентности. Проверьте канал перед ручной повторной отправкой, чтобы не создать дубль.

## Статистика

MAX доступен в общем разделе аналитики Postiz с периодами 7 и 30 дней:

- **Участники канала** — текущее значение `participants_count`, не прирост аудитории за период.
- **Публикации** — количество постов, опубликованных в канале за выбранный период, включая посты вне Postiz. Период включает сегодняшний день и предыдущие N−1 календарных дней по времени сервера.
- **Просмотры публикаций** — сумма текущих `stat.views` у этих постов. Это накопленные просмотры с момента публикации, а не просмотры, полученные за выбранные дни.

В статистике отдельного поста показываются его накопленные просмотры независимо от выбранного периода. MAX не предоставляет историю просмотров по дням: счётчики показаны как текущие значения с пояснениями, без выдуманного графика или процента роста. Отсутствующий счётчик не заменяется нулём. Общий счётчик просмотров скрывается, если хотя бы у одного поста нет `stat.views`.

Список постов читается страницами по 100 с перекрытием границы времени и устранением дублей. Если MAX не позволяет продвинуться дальше по страницам или период требует более 100 запросов, неполный итог не выдаётся. API провайдера просит сократить период; общий сервис Postiz при ошибке провайдера возвращает пустую аналитику. Аналитика канала использует существующий часовой кэш Postiz в production.

Перед отправкой комментария и чтением статистики поста проверяется его принадлежность подключённому каналу, в том числе для общего бота Juls. Чтение и модерация входящих комментариев в эту интеграцию не входят. Подписка на webhook не требуется.

## Эксплуатация

Используется `https://platform-api2.max.ru`, токен передаётся через заголовок Authorization. Доступ к API нужен процессу backend при подключении и orchestrator при публикации. Согласно документации MAX, среде может потребоваться доверенный сертификат Минцифры: добавляйте доверенный CA штатным способом (например, `NODE_EXTRA_CA_CERTS`), не отключайте проверку TLS.

Для обычных подключений Postiz токен хранится вместе с ID канала через существующий механизм шифрования (`JWT_SECRET`). Для управляемых Workspace Juls используется отдельная модель: общий токен бота задаётся только в runtime как `JULS_MAX_BOT_TOKEN`, а в записи канала остаются ID и маркер серверного секрета. Подключение разрешает только подписанный Juls endpoint после проверки, что подтверждённый через одноразовый код MAX-пользователь администрирует конкретный канал и бот имеет право публикации. Миграция базы не требуется.

Форма подключения с пользовательскими ключами использует общий POST endpoint вместо передачи ключей в адресной строке; состояние подключения расходуется однократно. Это правило применяется ко всем провайдерам с `customFields`.

## Проверка

`pnpm exec jest --config jest.max.config.cjs --runInBand`

`pnpm exec jest --config jest.formatting.config.cjs --runInBand`

`pnpm exec jest --config jest.max-ui.config.cjs --runInBand`

Ручная проверка после развёртывания в тестовом окружении:

1. Подключите тестовый канал, включите комментарии и выдайте боту `read_all_messages` и `write`.
2. Создайте пост и два текстовых комментария, для второго задайте задержку. В один комментарий вставьте форматированный текст и встроенную ссылку. Убедитесь, что URL виден в предпросмотре, а добавление медиа к комментариям недоступно.
3. Опубликуйте цепочку в тестовом канале: должен появиться один пост и два комментария под ним, с заданной задержкой и отдельными сохранёнными ID.
4. Откройте статистику поста и сравните просмотры с `GET /messages?message_ids=<mid>`. Проверьте раздел аналитики MAX: участники, публикации и накопленные просмотры за выбранный набор постов.
5. Проверьте существующее подключение через собственный токен и подключение через серверный токен Juls. Переподключение не требуется, если права бота уже достаточны.

Тесты используют ответы API-заглушки. Реальная публикация требует токена бота и тестового канала и в рамках разработки не выполнялась.

Проверка изменений 27 сентября 2026: 100 тестов прошли (87 MAX/DTO/очереди, 10 форматирования/Telegram, 3 рендеринга аналитики). TypeScript проверен для frontend, backend и orchestrator. `git diff --check` прошёл. ESLint не дошёл до проверки файлов: существующая конфигурация `eslint.config.mjs` падает в `FlatCompat` с `Converting circular structure to JSON`. Из дополнительного набора Juls прошёл тест telemetry; 32 теста с базой данных пропущены самим набором без тестовой БД. Развёртывание и реальная отправка в канал не выполнялись.
