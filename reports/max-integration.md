# Подключение канала MAX

В Postiz добавлен провайдер `max`: публикация сразу и по расписанию через собственного бота. Отдельное подключение для каждого канала; один бот может обслуживать несколько каналов.

## Подключение

1. Создайте бота на платформе [MAX для бизнеса](https://business.max.ru). Скопируйте его токен: Чат-боты → ваш бот → Расширенные настройки → Настроить.
2. Добавьте бота в канал администратором и разрешите публикацию (`write`).
3. Получите числовой `chat_id` канала из события `bot_added` вашего бота. Для бота с настроенным webhook событие приходит на его обработчик. Для нового бота без webhook можно получить событие через `GET /updates` при первоначальной настройке. Если событие уже потеряно, удалите и заново добавьте бота в канал после настройки получения событий. Не отключайте действующий webhook ради подключения Postiz.
4. В Postiz выберите «Добавить канал» → MAX. Введите токен бота и `chat_id`, включая минус, если он есть. Ссылка `max.ru/...` вместо ID не подходит.
5. После подключения создайте публикацию и выберите MAX. Для проверки подключения отправьте тестовый пост в свой тестовый канал.

[Официальная инструкция получения chat_id](https://dev.max.ru/docs-api#Получение-chat_id). С июня 2026 года `GET /chats` отключён: автоматический список каналов через этот метод не используется. Postiz не подписывает бота на события и не меняет его webhook.

## Поддержка

- Обычный текст и ссылки, до 4000 символов.
- До 10 вложений: изображения до 50 МБ каждое, видео до 250 МБ каждое. Ограничения форматов и размеров изображения (до 7680 × 7680) дополнительно проверяет MAX.
- Публикация только с медиа, без текста.
- Повтор отправки при явных ответах `attachment.not.ready` и HTTP 429, без повторной загрузки файлов.
- Комментарии и цепочки публикаций пока не поддерживаются.
- Ссылка на публикацию берётся из ответа MAX. Если MAX её не возвращает, Postiz сохраняет ID поста без выдуманной ссылки.

При сетевом сбое или HTTP 5xx во время отправки провайдер не повторяет запрос автоматически: MAX не предоставляет ключ идемпотентности. Проверьте канал перед ручной повторной отправкой, чтобы не создать дубль.

## Эксплуатация

Используется `https://platform-api2.max.ru`, токен передаётся через заголовок Authorization. Доступ к API нужен процессу backend при подключении и orchestrator при публикации. Согласно документации MAX, среде может потребоваться доверенный сертификат Минцифры: добавляйте доверенный CA штатным способом (например, `NODE_EXTRA_CA_CERTS`), не отключайте проверку TLS.

Для обычных подключений Postiz токен хранится вместе с ID канала через существующий механизм шифрования (`JWT_SECRET`). Для управляемых Workspace Juls используется отдельная модель: общий токен бота задаётся только в runtime как `JULS_MAX_BOT_TOKEN`, а в записи канала остаются ID и маркер серверного секрета. Подключение разрешает только подписанный Juls endpoint после проверки, что подтверждённый через одноразовый код MAX-пользователь администрирует конкретный канал и бот имеет право публикации. Миграция базы не требуется.

Форма подключения с пользовательскими ключами использует общий POST endpoint вместо передачи ключей в адресной строке; состояние подключения расходуется однократно. Это правило применяется ко всем провайдерам с `customFields`.

## Проверка

`pnpm exec jest --config jest.max.config.cjs --runInBand`

Тесты используют ответы API-заглушки. Реальная публикация требует токена бота и тестового канала и в рамках разработки не выполнялась.
